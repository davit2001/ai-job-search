# Behavioral Profile

## Overview
Davit's behavioral profile is that of a **proactive technical leader** — someone who identifies problems independently, proposes concrete solutions backed by data, and follows through to measurable outcomes. He combines strong execution skills with a collaborative mentoring instinct.

## Core Behavioral Drives

| Drive | Level | Meaning |
|-------|-------|---------|
| Initiative | High | Proactively identifies and proposes improvements without being asked (e.g., PixiJS proposal, Datadog integration) |
| Results-orientation | High | Consistently measures and reports outcomes (30%, 40%, 60% improvements) |
| Collaboration | Moderate-High | Mentors peers, writes documentation, shares best practices |
| Detail / quality | High | High test coverage (80%), ESLint/Prettier enforcement, performance budgets |

## Strongest Behaviors
- **Proactive problem identification:** Spots bottlenecks before they become blockers — proposed PixiJS for rendering, Datadog for observability, CI/CD improvements
- **Outcome-focused execution:** Every initiative is tracked to a measurable metric (load time %, deployment time %, code coverage %)
- **Knowledge multiplier:** Builds documentation and mentors others so knowledge doesn't stay siloed
- **Architecture thinking:** Reaches for systemic solutions (Turborepo monorepo, UI SDKs, design systems) rather than one-off fixes

## How You Work Best
- Small-to-mid-sized product engineering teams where ownership is clear and scope is real
- Async-first remote culture with clear written communication (proven at Partao, Luxembourg-based)
- Greenfield or migration projects where architectural decisions matter (not just feature factories)
- Environments that value testing, documentation, and code quality alongside shipping speed

## Growth Areas (frame positively in applications)
- **Backend breadth:** Has built APIs with NestJS and worked with PostgreSQL, but backend is secondary to frontend depth — frame as "full-stack capable, frontend-specialized"
- **Large-enterprise scale:** Experience is in startups and product companies; enterprise-scale systems are adjacent, not primary

## Mapping to Job Posting Language

When a job posting mentions these keywords, it's a **strong behavioral fit**:
- "ownership," "autonomy," "self-directed"
- "high-impact," "fast-paced," "startup environment"
- "technical leadership," "senior," "lead"
- "best practices," "code quality," "test coverage"
- "performance optimization," "scalability"
- "mentorship," "collaborative," "team player"
- "design system," "component library," "frontend platform"

When a job posting mentions these, flag as **potential friction**:
- "heavy process," "large committee-based decisions" — prefers lean decision-making
- "maintenance-only," "legacy systems" — energized by new builds and migration, not pure maintenance
- "on-call rotation" — no experience with production on-call at scale

## Management Style Preferences
- Managers who give clear goals and trust engineers to find the path
- Regular (but not excessive) check-ins; prefers async updates over status meetings
- Direct feedback culture — not highly political

## Using This in Applications
- **Cover letters:** Lead with outcomes (the numbers), then explain the approach that got there
- **CV:** Every bullet should have a metric or a concrete artifact — this profile demands it
- **Interviews:** Use STAR examples that feature proactive proposals (not just assigned tasks) and show both technical depth and team impact
- **Don't overstate:** Backend experience is real but secondary; don't claim backend as a primary skill in roles where it's the core requirement
